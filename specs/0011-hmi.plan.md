# Plan 0011: HMI devices, tags, connections, alarms and screens

## Order

TIA Portal V21 is a trial here, so the reference project comes first; the reader is then written against the committed archive without TIA.

1. Extend `tools/TiaOpennessExport` to build HMI devices and write what TIA says about them; build `tests/reference/Hmi`.
2. The reader in `src/TiaFormat`, test-first against the reference project and `TiaFileBuilder`.
3. `tiadump hmi` and the dump.
4. The viewer.
5. `docs/FORMAT.md` section 24, the glossary, the log.

## What TIA V21 allows here

Found with a probe project, outside the repository:

- **Devices.** The trial refuses Comfort and Basic panels ("WinCC Comfort" licence missing). It accepts an MTP700 Unified Comfort (`OrderNumber:6AV2 128-3GB06-0AXx/21.0.0.0`) with the WinCC Unified trial licence, and an ET 200SP Open Controller CPU 1515SP PC2 with WinCC RT Advanced (`OrderNumber:6ES7 677-2DBx2-0xx0/V21.9`), whose HMI runtime is a Comfort/Advanced device in the same model as a panel. The Open Controller brings its own software PLC.
- **Connections.** Both families take an integrated HMI connection from the hardware API: `CommunicationManagement.Connections.Create<HmiConnection>(local node, partner CPU, partner node)` on the HMI runtime's device item. The Unified panel connects over PROFINET to an S7-1500. The Comfort/Advanced runtime connects to its Open Controller's software PLC over the PC-internal subnet; to an outside PLC the connection is made, but no tag can be linked over it.
- **Unified** (`Siemens.Engineering.HmiUnified`): tags with `Connection` and `PlcTag` (a PLC tag or `"DB".member`), internal tags, tag tables, discrete and analog alarms (`RaisedStateTag`, `RaisedStateTagBitNumber`, `AlarmClass`, `Condition`, `ConditionValue`, `EventText` as `<body><p>…</p></body>`), screens and screen items with a `TagDynamization` on `ProcessValue`. All through the API, all readable back.
- **Comfort/Advanced** (`Siemens.Engineering.Hmi`): only SimaticML import and export, of tag tables and screens. Internal tags and tags with `Connection`, `AddressAccessMode` Absolute and `LogicalAddress` import. A link to a PLC tag does not: every name for it is refused (`'set_ControllerTag' is not supported`). Screens import as `Hmi.Screen.Screen` > `Hmi.Screen.ScreenLayer` (`Layers`, `Index`) > items (`ScreenItems`, `ObjectName`, geometry); a text is rich text. A tag binding does not import: `ProcessValue` is a link TIA knows on an I/O field, but import refuses to set it, and a `Hmi.Dynamic.TagConnectionDynamic` is not accepted in any composition tried. No alarms, alarm classes or recipes.
- An import TIA refuses while creating an object can end the Openness session; the build saves before each one.

So Comfort/Advanced alarms, tags linked to a PLC tag and screen items bound to a tag cannot be in the reference project. They are stored in the same types as Unified's (below), so the reader handles them by the same code, and `FORMAT.md` marks them **[I]** (FR-015).

## The reference project `Hmi`

`tests/reference/Hmi/sources/`:

- `PLC_Mixer/`: an S7-1500 as the other reference projects have, with a tag table and a data block of invented tank and mixer signals.
- `HMI_Panel/`: the Unified panel. `device.txt` names the device type and the PLC it connects to; `tags.tsv` (table, name, PLC tag or data type), `alarms.tsv` (kind, name, trigger tag, bit or limit mode and value, class, text), `screens.tsv` (screen, number, item, type, left, top, bound tag).
- `PC_Station/`: the Open Controller, its software PLC `PLC_Soft` with a tag table, and its WinCC RT Advanced runtime `HMI_Station`, with SimaticML tag tables and screens written for it.

The exporter's `reference` command learns these folders: a folder with `device.txt` is an HMI device; a PLC folder is built as before. After the build it writes `generated/<HMI device>/` from Openness: `connections.tsv`, `tags.tsv`, `alarms.tsv` and `screens.tsv` for Unified, read back from the API; for Comfort/Advanced, TIA's SimaticML export of each tag table and screen, and the connections from the hardware API. The archive goes into the repository as every reference archive does; the probe showed it at about 2.5 MB.

## Where the objects are stored

From the probe and two local samples (names only, no values):

| Object | Type | What the reader takes |
|---|---|---|
| HMI device | `HwConfiguration.Hmi.Model.HmiApplicationData` | Name; `Subtype` `HMI.Application.RT.IL` is Unified, `HMI.Application.RT` Comfort/Advanced; `IHmiApplicationAttributes.DeviceApplicationType`. Every HMI object's `Target`. |
| Connection | `Hmi.Utah.Communication.HmiConnectionData` | Name, `Subtype` (Integrated), `IHmiConnectionAttributes.PlcId`; `ConnectionPoint` → `HmiConnectionPointData` → `Conn2RemoteTargets` → `S7ControllerTargetData`, the PLC. |
| Tag table | `Hmi.Utah.Tag.HmiTagTableData` | Name, `Content` → tags, folder. |
| HMI tag | `Hmi.Utah.Tag.HmiTagData` | Name, `ITagAddress.LogicalAddress` and `AddressMode`, `IHmiTagBaseAttributes.AddressAccessMode`, `IStructureItem.DisplayTypeName`, relations `IHmiTagAttributes_Connection`, `IHmiTagAttributes_AcquisitionCycle` → `HmiCycleData`. |
| PLC link | `DomainModel.LinkMaintainer.ScopedLinkMaintainerData` | One per tag table: `Consumer` lists its HMI tags, `Provider` each PLC tag (`EAMTZTagData`) or data block (`DataBlockData`) they read, once. A tag linked to a PLC tag holds its address; a tag linked to a member has the expando `TypeSafeAddress` (a structure: `CRC`, `LidPath`, `Rid`), whose `Rid` names the data block's number and whose path the member's `LID`s and array indexes, matched against the data block's interface (section 11). |
| Discrete alarm | `Hmi.Utah.Alarm.HmiDiscreteAlarmData` | Name, `IHmiScadaAlarmAttributes.UniqueId` (Unified) or `IAlarmData.AlarmId`, `IHmiDiscreteAlarmAttributes.TriggerBitNumber`, `IHmiDiscreteAlarmAttributes_TriggerTag`, `HmiAlarmClassDataRelation`, text in `ExpandoChildren` → `HmiTextData`, a core text. |
| Analog alarm | `Hmi.Utah.Alarm.HmiAnalogAlarmData` | As above, `IHmiAnalogAlarmLimitAttributes.LimitMode` and `LimitValueConstant`, `IHmiAnalogAlarmAttributes_TriggerTag`. |
| Screen, Comfort/Advanced | `Hmi.Utah.GraphX.HmiScreenData` | Name, `IHmiScreenAttributes` Number, Width, Height; `Children` → items. |
| Screen item, Comfort/Advanced | `Hmi.Utah.GraphX.HmiScreenItemData` | Name, `Subtype` (TextField, IOField, ...), `IHmiScreenItemAttributes` geometry; bound tags through `ExpandoReferences` → `HmiTagData` as on Unified; the samples' HMI tags have such inverse relations from screen items. |
| Screen, Unified | `Hmi.DL.ModernUI.ILScreenData` | Name; size and number in dictionary expando values under short keys (format page, section 24). |
| Screen item, Unified | `Hmi.DL.ModernUI.ILScreenItemData` | Name, `Subtype` (HmiIOField, HmiText, HmiButton), geometry under the same short keys; bound tags through `ExpandoReferences` → `HmiTagData`. |

Runtime users (`HmiRTUserData`) and the device's `Password` stay unread (FR-016).

## Modules

- `Storage/TiaDatabase`: `ReadExpandoValueBytes`, the bytes of an out-of-line structure value of a dictionary expando (`TypeSafeAddress`). The Unified screens' short keys are ordinary dictionary expando keys.
- `Program/TiaHmi`: finds the project's HMI devices (`HmiApplicationData` in `ProjectData`) and reads them into a `TiaHmiReport`: devices, connections, tag tables and tags with their PLC links, alarms, screens and items. It resolves PLC tags and data block members through `TiaProgram`.
- `Program/TiaHmiWriter`: Markdown and JSON (`Utf8JsonWriter`), like `TiaOpcUaWriter`, and the dump's text files: per device `device.txt`, `connections.tsv`, `tags/<table>.tsv`, `alarms.tsv` and `screens/<screen>.tsv`.
- `Program/TiaHmiDocument`: the text the viewer shows for an HMI entry, a tag's PLC link a token that leads into the PLC's scope.
- `Program/TiaSourceExport`: writes an HMI device's files into `<project>/<HMI device>/`; nothing else in the dump changes (FR-010).
- `Program/TiaSecrets`: covers `HmiRTUserData` and `HmiRTGroupData` values.
- `src/TiaDump`: the `hmi` command with `--json` and `--device`.
- `src/TiaViewer`: an `HmiView` like `OpcUaView`; the tree gains HMI devices under the project with Connections, Tag tables, Alarms and Screens; a PLC link opens the PLC tag or data block through the existing navigation.

## Tests

- `tests/TiaFormat.Tests/TiaHmiTest.cs`: one test per acceptance scenario, named after it, on the reference project; `TiaHmiFixture` builds with `TiaFileBuilder` what it cannot hold: an HMI device in a master copy, an unresolved member, a tag of a structured type.
- `HmiReference` compares the report with `generated/<HMI device>/`, item by item (FR-014), in `TiaHmiTest`; the existing reference tests check the project's blocks and PLC tag tables as for every reference project.
- The dump of the reference project writes each device's folder beside the PLCs (`TiaHmiTest`).
- The viewer's tree, its entries' text and following a PLC link are in `TiaProjectHmiTest`, on the library's `TiaProject`; the window itself was checked by running the viewer.
- `--json` and `--device` are in `src/TiaDump`, which has no test project; checked by running the command, as for spec 0004.
