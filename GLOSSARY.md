# TiaTools

Reading Siemens TIA Portal projects, the files a PLC program is kept in, without TIA Portal.

This file is the glossary and nothing else: the project's own terms, one or two sentences each, opinionated, with the words to avoid. No general programming concepts, project facts, instructions or decisions; those live in `AGENTS.md`, `docs/`, `specs/` and `docs/adr/`. The name `GLOSSARY.md` is the one public domain-modeling skills look for (ADR 0004).

## Files

**Archive**:
A `.zap<NN>` file: a ZIP of a project folder, which TiaTools reads without unpacking it to disk.
_Avoid_: backup, zip file

**Project**:
The folder TIA Portal opens, by its `.ap<NN>` file; also loosely what an archive holds.
_Avoid_: solution, workspace

**Global library**:
An `.al<NN>` folder of master copies and types shared between projects.
_Avoid_: library archive

**Database**:
`System/PEData.plf`, the one file of a project or library that holds the program; what `docs/FORMAT.md` describes.
_Avoid_: PLF file, store

**Frame**:
One stored record in the database, followed by its hash; the last frame of an object is its current state.
_Avoid_: record, entry, page

**Object**:
One thing in the database, with a type id, an id and attributes, linked to others by relations.
_Avoid_: entity, node

## Program

**PLC**:
One controller in a project, with its own blocks and tag tables.
_Avoid_: CPU, device, station

**Block**:
A unit of the PLC program: an OB, FB, FC, DB or UDT, its kind.
_Avoid_: routine, POU, module

**Event class**:
What starts an OB: the program cycle, startup, a cyclic interrupt, an error and so on. TIA stores it as the OB's subtype.
_Avoid_: OB type, secondary type

**Program cycle OB**:
An OB whose event class is the program cycle: where the program's cycle starts, OB 1 `Main` in most programs. The viewer marks it in the tree.
_Avoid_: main OB, entry point, OB1 (as a name for the class)

**Tag table**:
A table of a PLC's tags and constants with their types, addresses and values.
_Avoid_: symbol table, variable list

**Watch table**:
A table of a PLC's operands to monitor and modify while the PLC runs, each entry with its name or address, display format, triggers, modify value and comment.
_Avoid_: variable table, VAT, watch list

**Force table**:
The one table per PLC of inputs and outputs to force while it runs, each entry with its name or address, display format, force value and comment.
_Avoid_: force list

**Cross reference**:
One use of an object, a block, tag, data block or member, by another object, with its access (read, write, call, instance, type, monitor, ...) and its place. TIA's cross-reference list, kept in the archive as `XRef.db`, holds those of the program; uses by watch and force tables are read from the tables.
_Avoid_: usage, xref (outside the format page), reference alone when the access matters

**Master copy**:
A copy of blocks kept in a project or global library for reuse; it can hold a whole other program, so one block name can occur several times for one PLC.
_Avoid_: template, library block

**Environment**:
Where a block lives: `ProjectData` for the project itself, or the master copy that holds it.
_Avoid_: scope, context

**Stub**:
A block object with no number, source or interface that refers to a block held elsewhere; left out when listing blocks.
_Avoid_: placeholder, dummy block

**External access**:
What an outside client (HMI, OPC UA, Web API) may do with a data block member or a PLC tag: read and write, read only, or nothing. TIA's settings `ExternalAccessible`, `ExternalWritable` and `ExternalVisible` taken together.
_Avoid_: exposed, public, visibility

**Node list**:
The nodes of a PLC's standard SIMATIC OPC UA server interface, with their node ids, derived from the program by the rules of TIA's node set export: `tiadump opcua --nodes`, and the viewer's Nodes tab. Written as a node set file by `tiadump opcua --nodeset` and Export node set.
_Avoid_: address space dump, tag list

**OPC UA report**:
What `tiadump opcua` writes per PLC: its OPC UA server's settings, roles and server interfaces, and the external access of its data blocks and tags.
_Avoid_: OPC UA export, address space dump

**Safety program**:
The fail-safe part of a PLC's program, which STEP 7 Safety compiles and signs: its F-blocks, F-runtime groups and settings. Only a PLC on an F-CPU has one.
_Avoid_: F-program, safety PLC, failsafe code

**F-block**:
A block of the safety program, written in F-FBD or F-LAD or generated by TIA, each with its F-signature.
_Avoid_: safety block, F-code

**F-runtime group**:
A part of the safety program that one F-OB calls, at its own cycle time, through its main safety block, with a maximum cycle time it must keep.
_Avoid_: safety task, runtime group on its own

**F-signature**:
The number TIA computes when it compiles the safety program: one per F-block, and the collective F-signature over the whole program, which tells whether two safety programs are the same.
_Avoid_: checksum, CRC, hash

**F-I/O**:
A fail-safe input or output module, which the safety program reaches by PROFIsafe.
_Avoid_: safety module, F-module

**F-parameters**:
The PROFIsafe settings of an F-I/O or the F-CPU: F-source and F-destination address, F-monitoring time, and the F-parameter signature over them.
_Avoid_: safety parameters, PROFIsafe settings

**Safety report**:
What `tiadump safety` writes per PLC, and the viewer's Safety entry shows: the safety program's settings, F-runtime groups, F-signatures and F-blocks, and the F-parameters. Whether a password is set, never more of it.
_Avoid_: safety export, safety printout

**Network**:
One unit of a LAD, FBD or STL block's logic, with its own number, title and comment; TIA stores each as a compile unit, and an SCL block has one.
_Avoid_: rung, segment, compile unit (outside the format page)

**Technology object**:
A configured instance of a Siemens technology function on a PLC, such as an axis, a PID controller or a high-speed counter, with its kind and version. TIA stores it as a data block of a technology type; its settings are its parameters, named as TIA's parameter view names them (`DynamicLimits.MaxVelocity`).
_Avoid_: TO DB, technology DB (outside the format page), axis block

**Step time**:
A GRAPH step's maximum time, after which its supervision reports an error, and its warning time, after which it warns; TIA's export calls them `MaximumStepTime` and `WarningTime` (spec 0016).
_Avoid_: timeout, step timer

**ProDiag supervision**:
A check ProDiag makes on a Bool member of a function block or PLC data type, or on a global tag: of a kind (operand, interlock, action, reaction, position, text message, error message), with the state that triggers it, a delay, up to three conditions and a category (spec 0016). Not a GRAPH step's supervision, which is a condition of the step.
_Avoid_: alarm, monitor, watch

**ProDiag function block**:
A function block in language ProDiag that evaluates the ProDiag supervisions of the instances and data blocks assigned to it; TIA generates its content.
_Avoid_: diagnostic block, supervision block

**Classic CPU**:
An S7-300 or S7-400 CPU, as opposed to an S7-1500 or S7-1200: its blocks have standard access only, and its STL has S5 timers and counters.
_Avoid_: old PLC, legacy CPU

**Project language**:
A language the project keeps its texts in, such as de-DE; every title, comment, alarm text and text list entry has a text per project language, which may be empty.
_Avoid_: culture (outside the format page), locale, translation

**Editing language**:
The project language a person types texts in, and the one TIA's generated source and TiaTools write by default.
_Avoid_: default language, main language, UI language

**Reference language**:
The project language TIA shows beside the editing language for translating; the reader falls back to it when a text is empty in the language written. Not to be confused with a reference project.
_Avoid_: source language, base language

**Program alarm**:
An alarm a PLC program raises by calling `Program_Alarm` on an instance in an FB: its alarm class, priority and texts are configured, not coded.
_Avoid_: message, PLC alarm (as a name for this kind), event

**Associated value**:
A value a program alarm passes with its signal (`SD_1` to `SD_10`), which its texts show through a placeholder.
_Avoid_: process value, parameter, accompanying value

**Alarm class**:
A project-wide class of alarms, such as Acknowledgement, that says among other things whether an alarm must be acknowledged.
_Avoid_: alarm type, category

**Text list**:
A PLC's table of texts by value or range of values, in every project language, from which an alarm text can take a text.
_Avoid_: enum, lookup table, string list

**Closed**:
What a know-how protected block or an encrypted value is to TiaTools: the archive holds only its ciphertext, so TiaTools reports it as encrypted and renders nothing of its body; which other objects it uses, as TIA's cross-reference list keeps in clear, is shown (ADR 0015). Decryption is a separate capability it does not have (ADR 0011).
_Avoid_: locked, hidden, unreadable

## Hardware

**Device**:
One station of the project's hardware, such as an S7-1500 station with its CPU or an ET 200SP IO device; it holds device items. A PLC is the program of a CPU in a device.
_Avoid_: station, node, hardware (for one device)

**Device item**:
Anything in a device: a rack, a module, a submodule, an interface or a port, nested as TIA's device view nests them.
_Avoid_: component, part

**Module**:
A device item plugged into a slot of a rack, with an order number: a CPU, an interface module, an I/O module, a server module.
_Avoid_: card, board

**Interface**:
A device item that connects a device to a subnet, such as a PROFINET interface `X1` or a DP interface `X3`, with its addresses there: IP address, subnet mask and PROFINET device name, or PROFIBUS address. A port is a socket of an interface.
_Avoid_: node (TIA's name for the addresses' object, kept to the format page), port

**Subnet**:
A PROFINET/Industrial Ethernet or PROFIBUS network that connects interfaces.
_Avoid_: network (a block's network is something else), bus

**IO system**:
The IO devices an IO controller exchanges I/O with over one subnet: a PROFINET IO system or a DP master system, with a name and a number.
_Avoid_: master system (except in TIA's name DP master system), IO network

**IO controller**:
The interface that owns an IO system, such as a CPU's PROFINET interface or its DP interface as DP master.
_Avoid_: master

**IO device**:
A device assigned to an IO system, as a PROFINET IO device or a DP slave.
_Avoid_: slave, remote I/O, field device

**I/O address**:
A range of a device item's inputs or outputs in the process image: its kind, input or output, its first byte and its length, as in `I 10..13`.
_Avoid_: logical address, peripheral address

**Hardware identifier**:
The number TIA gives a device item so the program can address it, held in a system constant such as `Local~DI_Main`.
_Avoid_: HW ID (in prose), LADDR

## HMI

**HMI device**:
An operator panel or PC runtime in a project, with its own HMI tags, connections, alarms and screens; TIA calls its software an HMI application.
_Avoid_: panel (for all of them), HMI station, visualization

**WinCC family**:
Which WinCC an HMI device belongs to: Comfort/Advanced (panels and WinCC RT Advanced) or Unified. They share how tags, connections and alarms are stored, not how screens are.
_Avoid_: HMI type, runtime (for the family)

**HMI connection**:
What an HMI device reads a PLC through: a name, the PLC and a communication driver.
_Avoid_: link, channel, PLC connection

**HMI tag**:
A tag of an HMI device: internal, or read over an HMI connection from a PLC tag, a data block member or an absolute address.
_Avoid_: HMI variable, PLC tag (which is the PLC's own)

**HMI alarm**:
An alarm an HMI device raises itself from an HMI tag: discrete, from a bit, or analog, from a limit. Not a controller alarm, which the PLC program raises.
_Avoid_: message, HMI message, event

**Alarm class**:
The class an HMI alarm belongs to, such as Alarm or Warning, which sets how it is shown and acknowledged.
_Avoid_: alarm type, priority

**Screen**:
One page of an HMI device's user interface, with its screen items.
_Avoid_: picture, view, page

**Screen item**:
One element on a screen, such as an I/O field or a text, with its position and size and the HMI tags it is bound to.
_Avoid_: object, widget, control (for all of them)

**HMI report**:
What `tiadump hmi` writes: each HMI device with its HMI connections, HMI tags, HMI alarms and screens (spec 0011).
_Avoid_: HMI export, HMI dump

## What TiaTools makes

**Dump**:
The files `tiadump dump` and the viewer's export write: one text file per block and tag table, and an `index.tsv`.
_Avoid_: extract, decompile, backup

**Generated source**:
The text TIA Portal writes with *Generate source from blocks*, which a dump matches for SCL blocks, data blocks and UDTs.
_Avoid_: export, SimaticML (which is TIA's XML export, a different thing)

**Texts table**:
The table a dump writes per PLC of every title, comment, alarm text and text list entry, one column per project language, as stored and with no fallback (spec 0014).
_Avoid_: translation table, language export

**Statement form**:
The text TiaTools writes for a LAD or FBD network or a GRAPH sequence, which TIA has no text for: its logic as SCL-like assignments and calls, a form of our own (ADR 0013).
_Avoid_: decompiled, SCL translation, pseudo code

**Comparison**:
`tiadump compare` of a dump against TIA's generated source, block by block.
_Avoid_: diff, test run

**Sample**:
A real archive the reader was checked on, named only by a letter (A, B) in this repository.
_Avoid_: the project's or plant's own name

**Demo project**:
The invented filling line shown in the README's pictures, the reference project `tests/reference/FillingLine`; with the other reference projects, the only projects whose content may appear in this repository.
_Avoid_: example project, test project

**Reference project**:
A small project TIA Portal built from invented sources, committed with its archive and the generated source TIA wrote for it, so the tests check the reader against TIA without TIA at hand (spec 0008).
_Avoid_: test project, fixture, golden file

## Repository

**Spec**:
The file in `specs/` that states what a feature must do: user scenarios, numbered requirements, success criteria. The source the code is built from.
_Avoid_: requirements doc, story, ticket

**Plan**:
The `.plan.md` file next to a spec that states how the feature is built.
_Avoid_: design, technical spec

**Bundle**:
The `docs/` folder as an Open Knowledge Format bundle: every page with frontmatter, an index, a log.
_Avoid_: wiki, knowledge base

**Router**:
A `CLAUDE.md` whose only content is `@AGENTS.md`.
_Avoid_: stub, link file
